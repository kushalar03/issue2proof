# Final demo video storyboard

Final length: 2 minutes 41 seconds. Capture at 1920 × 1080 with the full browser
viewport visible. Keep subtitles in a dedicated bottom band and never place them
over controls, code, evidence, or navigation. Use a visible cursor with a soft
highlight and pause briefly over every item named in narration.

## 0:00–0:18 · The problem and one-line pitch

**Visual:** Open the Overview page. Let the Memory Capsule orbit move for two
seconds, then point to “Evidence that survives the agent.”

**Narration:**

> Coding agents can already edit code and run tests. The missing layer is durable,
> executable evidence about failures that were fixed before. Issue2Proof is
> regression memory for AI coding agents that survives the agent.

## 0:18–0:38 · Novelty

**Visual:** Move to the “missing layer” comparison, then use the Memory page. Point
to the claim, frozen regression, provenance, and boundaries in the capsule.

**Narration:**

> Repository rules and agent memory preserve useful guidance. Issue2Proof adds a
> versioned Memory Capsule: the behavioral claim, exact frozen regression, hashes,
> assumptions, boundaries, and sandbox provenance. It is executable evidence rather
> than an unverified note.

## 0:38–1:20 · Working web product

**Visual:** Open Workspace. Click the Werkzeug example, show the reproduced failure,
candidate diff, passing regression, existing suite, and independent checks. Create
the Memory Capsule. Search for “Refactor safe_join path validation” and point to
the recalled claim and relevance.

**Narration:**

> A failure is imported from GitHub or a ZIP. Nemotron proposes a discriminating
> regression, but the original revision must fail it in a disposable Nebius
> Sandbox before repair begins. A candidate is accepted only after the frozen
> regression, existing suite, and withheld checks pass. The completed evidence can
> then become repository memory and be recalled for a later refactor.

## 1:20–1:59 · Real Codex MCP workflow

**Visual:** Use `submission/codex-mcp-demo.mp4`, generated from the fresh result in
`artifacts/codex-mcp-live-validation.json`. Point to the recall tool, capsule hash,
audit tool, assertion, conflict verdict, and bounded sandbox provenance.

**Narration:**

> The browser is only one client. Here a coding agent recalls the same verified
> contract through MCP before editing. It then submits the current local revision
> for independent replay. The fresh sandbox shows that the historical Windows
> behavior is violated, so Issue2Proof returns memory conflict instead of silently
> approving the change.

## 1:59–2:23 · AI and measured impact

**Visual:** Open Evidence. Let the counters animate, point to 3 of 8 versus 8 of 8,
then show the model-routing rows.

**Narration:**

> In thirty blind Nemotron refactor trials across two real bug histories, eight
> changes reintroduced the historical failure. Plain visible CI caught three;
> capsule replay caught all eight. Nano indexes memory, Qwen retrieves meaning,
> Super handles engineering and conflict analysis, and Ultra is reserved for
> escalated high-risk uncertainty.

## 2:23–2:41 · Honest close

**Visual:** Point to the evidence limitation, then return to the Overview headline.

**Narration:**

> A passing replay is not universal correctness. It means the selected frozen
> behavior passed in the recorded environment. Git records what changed.
> Issue2Proof preserves why the behavior must keep working—and checks it again.

## Audio and edit requirements

- Use a calm technical voice at roughly 145 words per minute.
- Generate narration sentence by sentence so punctuation and technical terms remain
  natural. Pronounce MCP as “M-C-P”, SHA-256 as “S-H-A two-fifty-six”, Nebius as
  “NEH-bee-uhs”, and Nemotron as “NEM-oh-tron”.
- Align every sentence to the visual action it describes. Do not reuse a continuous
  audio take after changing visual timing.
- Keep music at least 18 dB below narration and remove it during terminal evidence.
- Use 150–250 ms crossfades only at chapter boundaries. Avoid decorative transitions
  during code, audit output, and verdicts.
