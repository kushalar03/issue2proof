Issue to Proof turns a Python bug report into a repair you can review, with actual execution evidence. A plausible patch is only the beginning. The important question is whether it fixes the reported behavior without breaking something else.

This demonstration replays saved evidence from real Nebius runs. Viewing the evidence makes no paid requests. In this first run, NVIDIA Nemotron on Nebius Token Factory generated a repair. The original regression failed, and the candidate passed the regression, existing tests, and independent boundary checks.

The uploaded project workflow goes further. You upload a focused Python project, describe the expected behavior, and reserve independent tests. Their contents stay outside the model context. Nemotron generates a regression and a patch. The application freezes the tests before remote verification.

Each check starts in a fresh disposable Nebius Sandbox, with networking disabled. Repository code runs without root privileges, with time, memory, and process limits. File hashes and execution results accompany the candidate patch.

Here is why independent checks matter. This deliberately bad repair returns zero for every input. It passes a narrow regression, but breaks ordinary totals. The verifier rejects it.

Issue to Proof does not claim universal correctness. It reports the checks that passed, their limits, and the evidence behind the result. The release includes runnable source, tests, live reports, and downloadable repair artifacts.
